# 第五轮隐蔽缺陷审查报告

审查日期：2026-10-09。基线：`v1.1.9`，提交 `c7ae139710fd293727177a6cb809fd762e52b23c`。后续实现与验证见[第五轮修复验收报告](project-fifth-repair-report.md)。

## 结论与范围

本轮由 9 个模块子代理及 1 个 OCR 子代理并行执行，主代理收齐结果后复核、去重并补充原生 XHR 探针。确认 3 项新问题：1 项 P2 用户交互缺陷、2 项 P3 接口契约缺陷。没有确认 P0/P1。生产代码未修改，未提交或发布。

主要用户影响来自 Tabview 自建交互控件：鼠标点击可以工作，但标签和字号按钮不能获得键盘焦点，键盘用户无法完成对应操作。另外两项有明确边界：翻译参数插值接口当前没有生产调用；XHR 问题要求在已有请求进行期间，对同一实例执行会抛错的重开调用。不能将这两项描述为普通 YouTube 使用中普遍发生的故障。

覆盖运行时与启动、DOM 发现、存储、桥接、配置拦截、Trusted Types、构建与 CI 配置、设置与特性注册、语言、主题、广告标注、播放器与快捷键、字幕网络及状态、网格、模态框、工具栏、下载、Tabview 会话、原型钩子、导航适配、DOM 搬运、镜像与尺寸。与[第四轮审查报告](project-fourth-audit-report.md)、[第四轮修复报告](project-fourth-repair-report.md)及前三轮去重。

“确认”表示实现错误和触发条件已有源码及定向复现支持；真实 YouTube/Tampermonkey/Violentmonkey 端到端、辅助技术及长时间浏览器会话尚未验收。

## 确认问题

| 编号 | 优先级 | 问题 | 影响边界 |
| --- | --- | --- | --- |
| K01 | P2 | Tabview 标签与字号控件无法通过键盘操作 | 启用 Tabview 后，使用键盘切换标签或调整字号 |
| K02 | P3 | 翻译参数中的美元替换序列被重新解释 | 调用 `Locale.t(key, params)`；当前未找到生产插值调用 |
| K03 | P3 | XHR 重开抛错会提前结算仍在运行的字幕请求 | 同一 XHR 正在请求字幕，第二次 `open()` 在原生参数校验阶段抛错 |

### K01：Tabview 标签与字号控件无法通过键盘操作

位置：[标签与字号模板](../src/features/tabview/page/tabs-view.ts)，247–285 行；[事件处理](../src/features/tabview/page/tabs-view.ts)，299–350 行；[样式](../src/features/tabview/tabview.css)。

标签采用没有 `href` 或 `tabindex` 的 `<a>`；字号控件采用普通 `<div>`，没有按钮语义、可访问名称或焦点属性。委托事件只监听 `click`，没有对应键盘操作。字号控件的显隐还依赖鼠标悬停。

因果链：启用 Tabview 后，原生内容被放入不同面板；用户用 Tab 导航时无法进入标签控件，也无法通过 Enter/Space 激活字号控件。即使给元素派发键盘事件，现有处理器也不会切换标签或调整字号。该问题不依赖特殊上游 DOM 顺序，与第二轮工具箱、第三轮 Shorts 下载入口、第四轮模态框的键盘修复属于不同入口。

复现：调用 `TabsView.render()` 将控件挂入文档，分别对 comments 标签及 info 的字号加号调用 `focus()`，焦点不会进入目标；派发 Enter 后活动标签和字号保持不变。子代理的临时 Vitest 探针成功断言上述缺陷状态，1 项通过；通过表示复现成立，不表示功能符合预期。

验收要求：标签和字号操作都可通过键盘访问；具备正确语义、名称和当前状态；鼠标与键盘调用同一业务行为且一次操作只执行一次；焦点进入控件时字号操作可见。改用原生控件时需协调模板结构，避免嵌套交互控件，并验证语言更新、评论计数、字号上下限和面板切换。

### K02：翻译参数中的美元替换序列被重新解释

位置：[翻译插值](../src/i18n/index.ts)，53–59 行。

`Locale.t()` 先转义参数中的 HTML 字符，再将结果作为 `String.replace()` 的字符串 replacement 传入。replacement 中的 `$$`、`$&` 等序列具有替换语义，并不表示按原样插入参数。这个二次解释使合法参数值损坏。

主代理复现使用不涉及 HTML 转义的值，注册当前语言消息 `Value: {value}`，调用：

```ts
Locale.t("audit_value", { value: "$$" });
```

预期 `Value: $$`，实际 `Value: $`。此结果通过直接加载当前 TypeScript 实现的 Node 探针确认。`$&` 的例子还受到既有 HTML 转义影响，验收应同时区分转义结果和 replacement 解释，不能混为一项输出错误。

影响限于插值接口：当前生产代码未找到传入 `params` 的调用，因此没有证据表明现有设置或 Tab 标签已出现文案损坏。

验收要求：参数按既定转义规则生成后作为字面值插入，不再解释美元替换序列；覆盖 `$$`、`$&`、前后文替换序列、普通文本、数值、HTML 字符及同名占位符重复出现。

### K03：XHR 重开抛错会提前结算仍在运行的字幕请求

位置：[XHR open 包装](../src/features/caption/interceptor.ts)，338–348 行；[失败结算](../src/features/caption/interceptor.ts)，376–383 行。

包装器在调用原生 `open()` 前就恢复响应头方法、结算旧请求失败、撤销监听并覆盖实例标记。原生调用如果在参数校验阶段抛错，旧网络请求并没有被终止，但拦截器已经失去旧请求的有效所有权。

原生契约依据：[WHATWG XMLHttpRequest 的 open 算法](https://xhr.spec.whatwg.org/#the-open()-method)先校验 method、URL 等条件，再终止既有 fetch。因此参数校验抛错不能被视为旧请求已取消。

主代理使用真实 jsdom `XMLHttpRequest` 和本地 HTTP 服务复现，未用模拟 `open()` 替代原生行为：

1. 安装当前拦截器，以非零偏移发起 `/api/timedtext?v=video&lang=en`，服务端暂缓响应。
2. 对同一实例执行 `open("invalid method", anotherUrl)`，捕获 `SyntaxError`。
3. 服务端返回有效 JSON3 字幕，等待原请求完成。

观测：抛错后 `readyState` 仍为 1；原请求最终到达 4、状态为 200，但回调序列只有 `started → failed`，没有 `ingested`；读取正文得到未应用偏移的原始数据。子代理的标准顺序模拟探针也复现了相同所有权错误。

本项是异常路径的接口兼容性缺陷。探针故意制造原生应抛出的异常，用于验证旧请求状态是否保留；尚无证据证明 YouTube 正常字幕调用会执行这种失败重开，不能扩展为普通请求必现的字幕丢失。

验收要求：原生 `open()` 校验失败时保留旧请求的监听、所有权、正文和响应头装饰；真正成功重开时仍结算旧请求并正确登记新目标。修复需覆盖原生同步事件重入，不能仅调整语句顺序而忽略 `readystatechange` 中再次调用 `send()` 的情况。
