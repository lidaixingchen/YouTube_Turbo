# 第二轮缺陷修复方案

## 目标与边界

落实 [第二轮审查报告](project-second-audit-report.md) 的 N01–N12，保留功能 ID、设置持久化优先级、默认值与描述符顺序。验收必须覆盖已保存的关闭状态、生命周期失败后的重试、恢复原 DOM、失败请求后的字幕校准、键盘操作和实际构建插件更新。条件性风险按报告中的决定性验证条件处理。

## 启动与状态所有权

入口先提供设置菜单、工具栏和功能注册，再由注册表调度功能初始化。共享播放器只在需要它的功能 setup 中初始化；存储读取失败不确认完成状态，释放已获取资源并允许后续重试。播放器基础初始化不自行恢复循环，循环描述符在获准启用后读取并应用已保存的循环选择。下载服务仅由下载描述符启停，菜单文案使用 `action_setting`。

## 下载媒体身份与 HUD

watch 和 Shorts 使用有效路由视频身份，保留操作开始时的完整地址。首页和订阅页的迷你播放器缺少已确认的视频身份来源，下载动作保持隐藏并停止执行。HUD 在当前播放器范围内复用或创建自身节点，切换播放器时释放自身旧资源。

## 搬运与注入

Relocator 的每条搬运路径均登记源父节点、邻接位置及锚点；优先恢复到有效锚点，锚点移除时用仍有效的源位置恢复。源父节点消失时仍保全内容节点的所有权，卸载不能把它随 Tabs 容器删除。重复同步复用恢复记录，节点物理移动继续遵守静默锁。

只有 `GM_addElement` 返回注入元素才确认成功。返回空值或抛错时走已有备用注入流程，并使协议失败能够明确结算。

## 字幕失败结算

fetch 与 XHR 保持共享的每视频请求顺序及启用周期隔离。请求失败、中止、超时或错误响应通过带序号的失败结算释放恢复权，只有仍为最新请求的失败可以改变恢复状态。最近成功轨道及缓存必须保留，旧失败不能覆盖后来的成功。最新请求仍在途时，不允许过期响应经缓存回退抢占；失败后才能选择相应的有效恢复轨道。原生基准偏移与会话覆盖层的分工保持不变。

## 键盘交互

工具箱、倍速触发器和菜单选项使用原生按钮。Popover 支持 Enter/Space 激活、焦点进入菜单、方向键导航、Home/End、Escape 关闭及焦点返回；Tab 离开后关闭。局部事件处理阻止被 YouTube 快捷键重复消费，保持现有 hover、触摸、外部点击和异步动作锁语义。销毁移除监听与定时器，不留下不可见的焦点节点。

## 多语言与开发构建

补齐现有字典的全部基础键，并为元数据声明的语言提供完整运行时翻译；区域标签可复用对应语言字典，RTL 方向显式设置。字典按文件分工维护，聚合入口保持 `DICTIONARIES`、`Locale` 和 `LangueUtil` 接口。测试检查基础键完整性及名称语言与运行时覆盖的对应关系。

页面 bundle 插件规范化路径、登记 esbuild 依赖，并把失效的虚拟模块传入 Vite 更新流程。构建与开发模式均使用当前页面源码，热更新验证覆盖 Windows 分隔符、页面依赖变更和关联虚拟模块更新。

## 验证与交付

- 各模块维护正式回归测试，覆盖缺陷触发、正常路径、失败重试和资源释放。
- 整合后串行执行严格类型检查、全量 Vitest 和生产构建，测试使用单个工作线程控制本机资源占用。
- 优先使用 pnpm；配置权限阻断时使用仓库已安装的 Node 工具执行等价脚本，不安装依赖或修改锁文件。
- 修复报告逐项记录最终实现、测试结果与仍需现场验收的条件；生产代码与注释保持终态，不记录试错过程。
