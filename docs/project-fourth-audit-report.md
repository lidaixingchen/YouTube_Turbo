# 第四轮隐蔽缺陷审查报告

审查日期：2026-10-07。基线：`v1.1.8`，提交 `c69b8019886a3b3ebcaea2b81df0a4c56143e96f`。后续实现与验证见[第四轮修复验收报告](project-fourth-repair-report.md)。

## 结论与范围

本轮由 10 个并行子代理完成模块审查与自动扫描尝试，主代理收齐结果后核对调用链、既有验收契约和证据。确认 8 项新缺陷：4 项 P2、4 项 P3；没有确认 P0/P1。生产代码未修改，未提交或发布。

主要问题是异步操作的所有权没有贯穿等待过程：切换字幕轨道只更新请求所有者，未撤销旧显示；下载动作只因计时到期便释放互斥锁，原确认操作仍可继续完成。模态框缺少焦点管理，使后台按钮还能通过键盘操作，进一步扩大重复执行的可达范围。

另外确认了字幕片段跨零时间计算、字号协议范围、国际化频道路径、安装入口版本及响应元数据的一致性问题。响应元数据和字号通知属于接口契约缺陷；实际页面调用方使用这些字段或事件的程度应单独说明，不能等同于普遍可见的界面故障。

审查覆盖运行时、启动与构建、注册表与设置、语言、主题、广告标注、播放器、字幕、网格、工具栏、模态框、下载、Tabview 页面会话、原型钩子、DOM 搬运、镜像、尺寸、导航适配。前三轮修复背景见[第三轮修复报告](project-third-repair-report.md)，本报告列出不同触发机制。

“确认”表示源码因果链及定向复现或静态版本证据成立；不表示所有场景都已在真实 YouTube 页面出现。真实 YouTube/Tampermonkey/Violentmonkey 端到端验收尚未进行。

## 缺陷证据与修复验收

### J01：新字幕轨道等待期间继续显示旧轨道

位置：[请求开始回调](../src/features/caption/controller.ts)，56–58 行；[轨道请求登记](../src/features/caption/timeline.ts)，194–204 行；[覆盖层读取](../src/features/caption/renderer.ts)，297 行附近。

控制器收到请求开始通知，只调用 `noteTrackRequest()`。该方法将视频 owner 改为新 key 的 `pending` 状态并重置游标，但保留 `currentCues`。渲染器按当前 cues 继续绘制，不检查它们是否属于新 owner。因此同一视频已显示 English，再请求 French 且响应尚未返回时，覆盖层仍显示 English。

这与有效空响应到达后清空显示是不同阶段的缺陷：本项发生在请求已经开始、尚未结算期间。既有时间轴测试中“等待时旧数据不活动”用例先显式调用 `clearCurrent()`，没有覆盖控制器实际请求开始路径缺少这一步的情况。

证据：临时探针先成功摄入 English，再登记不同 key 的 French 请求而不返回响应；`getActiveCueText()` 仍返回 English。内置控制器调用链与探针一致。可见影响要求会话偏移非零、覆盖层已激活；纯原生字幕显示不能据此认定受影响。

验收：仅当前视频的新轨道请求取得所有权时撤销旧轨道显示；其他视频的预取请求不能清空当前视频。不同轨道等待时不显示旧语言；同轨刷新策略应明确；新请求失败后按既有请求序号策略恢复有效缓存。

### J02：下载确认未结束时执行锁提前释放

位置：[动作执行锁](../src/ui/toolbar/toolbar.ts)，498–543 行；[超时常量](../src/ui/toolbar/constants.ts)，48 行；[下载确认](../src/features/download/index.ts)，24–54 行。

动作开始后，工具栏安排 5 秒看门狗。计时到期调用 `releaseLock()`，没有取消 `onClick()` 返回的 Promise。首次下载动作正在等待 `Modal.confirm()`，用户阅读超过 5 秒是正常操作，原 Promise 此时仍然有效。

锁释放后再次触发同一下载动作，会创建第二个确认框。分别确认两个框后，两份异步流程都调用 `openInTab()`，产生两次下载页面打开。执行代际只能阻止旧流程释放新锁，不能阻止旧流程继续执行下载副作用。

证据：临时探针使用真实下载服务、工具栏及确认路径，等待看门狗后重触发，观察到两个确认框和两次 `GM_openInTab`。探针通过 jsdom `.click()` 驱动按钮；真实浏览器的后台键盘重触发还依赖 J03 的焦点状态，尚未现场验证。它不是“网络超时已取消”，而是等待中的业务操作仍存活。

验收：合法用户确认期间保持互斥；如果采用超时策略，必须取消业务操作并使旧结果失效后才能允许重试。分别覆盖长时间确认、取消、异常、销毁，以及旧异步结果晚于新执行完成的顺序。

### J03：模态框缺少语义和焦点生命周期

位置：[模态框构造与关闭](../src/ui/modal/modal.ts)，27–117 行；[工具箱关闭恢复焦点](../src/ui/toolbar/popover.ts)，112 行附近。

模态框使用普通容器，未声明 dialog 角色或 `aria-modal`，没有将焦点移入弹窗，也没有限制 Tab 焦点或关闭后恢复焦点。键盘监听只处理 Escape。下载动作打开确认框后，工具箱关闭又把焦点还给后台触发按钮。

证据：真实下载调用链的临时探针确认弹窗显示时 `document.activeElement` 仍是后台工具箱按钮，且容器没有 dialog 语义。浏览器会把后续键盘操作交给当前焦点控件；遮罩只拦截指针，不约束键盘焦点。完整 Tab 顺序及辅助技术播报仍需浏览器验收。

验收：弹窗具有可访问名称及模态语义；打开时焦点进入合理控件，Tab/Shift+Tab 留在当前弹窗；后台交互被约束；关闭后恢复到仍有效的触发控件。设置表单和确认框都应覆盖，多个弹窗需要明确由最上层接管键盘。

### J04：README 安装入口仍指向旧版

位置：[安装与版本](../README.md)，7 行；[构建版本](../build/metadata.ts)，79 行；[包版本](../package.json)，5 行。

当前提交的包版本及构建元数据为 1.1.8，README 却显示 1.1.6，并将安装文件与发布说明固定指向 1.1.6。用户按仓库首页说明操作，会请求旧版附件。证据是同一提交中文档链接与版本声明直接不一致，无需构造异常输入。

验收：仓库安装入口与当前已发布版本一致；后续发布时同步版本文案、安装链接与发布说明链接，或者使用经过验证的 Latest 安装入口。不能仅修改显示版本而保留旧附件地址。

### J05：负偏移跨零时片段相对时间没有同步裁剪

位置：[JSON3 时间改写](../src/features/caption/interceptor.ts)，98–109 行；[片段类型](../src/features/caption/types.ts)，29 行附近。

JSON3 片段 `tOffsetMs` 相对于事件起点计时。事件整体平移后起点小于零时，代码把起点钳到零并缩短持续时间，却保留片段原来的相对偏移。

合法示例：事件起点 100ms，片段偏移 250ms，全局偏移 -200ms。片段原绝对时间为 350ms，平移后应为 150ms。实际事件起点变为 0，片段偏移仍为 250ms，使片段晚 100ms。这破坏了毫秒级偏移的计算契约。

证据：临时探针通过 `modifyPayload()` 确认结果仍为 250ms。影响主要是原生播放器消费改写 JSON3 时的逐片段时序；覆盖层当前将片段文本合并，不能声称其逐词展示也已验证。

验收：事件裁剪与片段时间统一计算，保留平移后的绝对时间；覆盖片段也跨零、事件完全结束于零之前、缺省片段偏移，以及没有下溢的正常事件。

### J06：字号控件与会话协议范围不一致

位置：[页面字号常量](../src/features/tabview/page/constants.ts)，226 行附近；[协议字号常量](../src/features/tabview/constants.ts)，16 行附近；[字号按钮](../src/features/tabview/page/tabs-view.ts)，326–342 行；[协议校验](../src/features/tabview/protocol.ts)，119 行附近。

页面允许 10–28px，协议只接受 10–24px。按钮先调用 `setFontSize()` 限幅，再将未限幅的 `nextSize` 传给通知回调。因此从 24px 点“+”后页面显示 25px，但会话拒绝对应 `font-size-changed` 消息。在页面上下限继续点击，还会发送超过实际显示范围的值。

证据：临时探针连接配对会话，从 24px 点击“+”，观察到页面变为 25px，接收端返回 `invalid-message` 而未交付字号事件。本地字号修改仍生效；当前沙箱没有使用该通知持久化字号，因此不报告已经发生的保存丢失。

验收：页面、bootstrap、命令和事件统一字号范围；按钮发送实际限幅后的值；覆盖最小值、24px、最大值和连续边界点击，配对会话应接受全部合法事件。

### J07：国际化频道 handle 无法触发简介预览

位置：[频道 About 正则](../src/features/tabview/page/constants.ts)，199 行；[About 路径识别](../src/features/tabview/page/minibrowser-router.ts)，65–73 行。

handle 正则只接受 ASCII 字符。YouTube 支持多语言 handle，且非 ASCII handle 从浏览器复制时使用标准 URL 编码；这属于合法上游输入。[YouTube 官方 handle 文档](https://support.google.com/youtube/answer/11585688?hl=en)说明了多语言字符与编码 URL。

迷你播放器保留条件成立时，导航包装器只在路径匹配后安排简介弹窗。编码后的 `/@東京/about` 不匹配，于是原生导航仍执行，但简介预览按钮未被自动点击。

证据：临时探针通过实际导航包装器输入编码路径，确认原生导航被调用、弹窗按钮未点击；ASCII handle 既有用例正常。未声称所有频道导航都失败，也未阻断原生导航。

验收：按 URL 路径结构识别频道与 `/about`，支持编码后的国际化 handle；覆盖中文、日文、阿拉伯文、合法分隔符及常规 ASCII 路径，并保留导航取消和新导航覆盖旧任务的机制。

### J08：改写字幕正文后响应元数据失真

位置：[fetch 替换响应](../src/features/caption/interceptor.ts)，261–267 行；[XHR 响应 getter 替换](../src/features/caption/interceptor.ts)，430 行附近。

非零全局偏移路径用 `new Response()` 替换正文，只复制状态及 headers。新 Response 的 `url`、`redirected`、`type` 分别变成空字符串、`false`、`default`。若原响应暴露正文表示长度，复制的 `Content-Length` 也不会随正文改写更新；XHR getter 路径同样没有协调表示头。

证据：临时探针确认 fetch 可观察属性丢失，以及改写后仍保留旧长度头。偏移为零、停用与错误回退路径返回原始 Response，不受此项影响。

这是已复现的网络接口兼容性缺陷。页面调用方若只读取正文，元数据差异未必造成可见故障；当前没有真实 YouTube 依赖这些字段或头部的样本，不据此报告网络请求普遍失败。表示头还涉及压缩和解压语义，不能简单将 JavaScript 字符串长度当作网络字节长度。

验收：在改写正文时保留调用方可观察的响应身份和元数据，协调失效的表示头；覆盖属性、正文读取、clone 与 XHR getter 行为，并保持原生响应回退契约。

## 仍需现场样本的边界

以下没有计入 8 项确认缺陷；优先取得真实上游事件或节点样本，再决定是否修改架构。

| 边界 | 本轮证据 | 缺少的关键事实 |
| --- | --- | --- |
| 播放器旧视频仍连接，新活动视频尚未触发 play | 控制器保留旧绑定，导航查找与 play 接管之间存在窗口 | YouTube 实际节点顺序及活动视频标记，特别是 Shorts |
| 网格上游移动已被脚本重排的节点 | 源位置锚点恢复会把节点送回原位置，原生观察器探针可复现 | 上游是否复用并移动这类节点 |
| 同路由替换网格 `#contents` | 旧目标监听无法发现新目标，探针可复现 | YouTube 是否执行该替换而不发相应路由事件 |
| 静默窗口内同步追加网格节点 | 自定义元素重连回调追加可被整批静默丢弃 | 实际上游生命周期是否同步产生这类额外突变 |
| 播放中单独替换 CC 按钮 | 新按钮关闭状态未被旧按钮观察器接收，DOM 探针可复现 | YouTube 是否在当前播放器会话执行该替换 |
| 页面 main 强行建立重叠会话 | 旧会话 teardown 可销毁共享协调器 | 内置沙箱会等待 teardown ack 并阻止重叠 setup，当前没有绕过这一约束的内置路径 |
| 跨 realm 的 `GM_addElement` 返回值 | `instanceof` 可能不满足，导致回退注入 | 真实油猴返回值 realm、CSP 与插入行为 |
| 评论链接参数中的 CSS 特殊字符 | 构造 `lc=%22` 可使选择器异常 | 尚无证据表明 YouTube 生成的合法评论 ID 包含这类字符 |

## 修复排序

优先修复 J01 的轨道显示所有权，并将 J02/J03 合并为异步确认与模态焦点修复批次。J04 应在下一次交付前同步安装入口。随后处理 J05 的时间计算、J06 的协议范围和 J07 的合法路径兼容。J08 需要按原生响应接口设计并验证元数据保留，避免为少数属性引入破坏 clone 或 body 读取的包装。

修复测试应断言正常行为，分别覆盖用户长时间阅读、同一视频切轨、事件与片段跨零、协议边界点击、编码频道路径及偏移响应读取。条件性边界先补充真实上游样本，单独评估。
